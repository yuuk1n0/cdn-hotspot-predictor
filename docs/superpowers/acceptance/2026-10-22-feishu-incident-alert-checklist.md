## 2. 已覆盖的自动测试

### 2.1 路由与配置

- [x] 新 AppID 默认关闭告警，P1 自动建群默认开启。
- [x] 配置使用 `expectedVersion` 防覆盖。
- [x] AppID 配置相互隔离。
- [x] 启用告警必须配置负责人、固定群和业务名称。
- [x] P1 自动建群必须配置备份负责人。
- [x] 非告警字段不能通过告警接口修改。

### 2.2 飞书客户端

- [x] 租户令牌缓存，不在每次请求时重复获取。
- [x] 创建私有群、拉成员、发送 Card 2.0 卡片和校验群/用户。
- [x] 401 和 `99991663` 刷新令牌一次。
- [x] 429、5xx 标记为可重试。
- [x] 部分成员未入群不会标记为完全成功。
- [x] 凭证不进入响应、记录或错误消息。

### 2.3 事故状态机

- [x] 相同 `appId + incidentType + objectKey + activeWindow` 只创建一个活跃事故。
- [x] 后续异常更新原事故并增加发生次数。
- [x] `sourceEventId` 幂等。
- [x] 两个 AppID 不串事故。
- [x] 恢复后允许同指纹创建新事故。
- [x] 跨 App 恢复被拒绝。

### 2.4 群路由和卡片

- [x] P1 自动建群并拉入负责人、备份负责人。
- [x] P1 建群失败回退固定群，后续不重复建群。
- [x] P2/P3 只发固定群。
- [x] Card 2.0 包含事故号、状态、时间、对象、当前值、阈值、影响和负责人。
- [x] 负责人使用 `<at id=ou_xxx></at>`。
- [x] 更新卡发送到原事故群。
- [x] 恢复卡发送到原事故群。
- [x] 建群、拉成员、卡片和恢复动作分别写入投递记录。

### 2.5 提醒与回调

- [x] 超时后按提醒间隔发送未处理提醒。
- [x] 同一时刻重复 tick 不重复提醒。
- [x] 认领后停止提醒。
- [x] 恢复后停止提醒。
- [x] 只有负责人或备份负责人可以操作。
- [x] 操作人身份只来自飞书回调。
- [x] verification token 校验。
- [x] `X-Lark-Signature` 官方 SHA-256 算法校验。
- [x] AES-256-CBC 加密回调解密。

### 2.6 前端

- [x] 实时告警、业务通知配置、发送记录三个页签。
- [x] 按 AppID、状态和等级查询事故。
- [x] 事故详情展示当前值、阈值、影响、负责人、事故群和投递轨迹。
- [x] 页面不发送自报 `openId`。
- [x] 测试卡片只允许使用 `testChatId`。
- [x] 原有每日清单、逾期提醒和发送记录能力仍保留。

## 3. 浏览器验收

前置条件：

1. 目标 MySQL 已人工确认并执行 `006_incident_alerts.sql`。
2. Java 使用目标环境启动。
3. Vue 使用同一 API 环境启动。
4. 准备两个 AppID 的独立测试路由。

- [ ] 新增 AppID `10350` 和 `10066`，配置不同负责人、固定群和测试群。
- [ ] 保存后刷新，两个 AppID 的配置不串值。
- [ ] `10350` 的告警只出现在 `10350` 筛选下。
- [ ] `10066` 的告警只出现在 `10066` 筛选下。
- [ ] 事故详情显示事故号、对象、当前值、阈值、影响和路由状态。
- [ ] 投递轨迹显示群创建、成员邀请和卡片阶段。
- [ ] 页面只显示复制群 ID，不显示网页认领或恢复写按钮。
- [ ] 测试发送弹窗明确标注 DEMO，并只发送到测试群。
- [ ] 失败或未知投递显示具体阶段和错误码。
- [ ] 移动端宽度下事故列表和详情可正常查看。
- [ ] 键盘 Tab 可以访问所有筛选、配置和按钮。

## 4. 真实飞书验收

必须使用用户明确授权的测试群和应用机器人，不在自动测试中调用。

- [ ] 应用已配置 `FEISHU_APP_ID`。
- [ ] 应用已配置 `FEISHU_APP_SECRET`。
- [ ] 应用已配置 `FEISHU_VERIFICATION_TOKEN`。
- [ ] 应用已配置 `FEISHU_ENCRYPT_KEY`，或明确接受仅 verification token 的低安全模式。
- [ ] 应用已开通建群、拉成员、发送消息、群信息读取和负责人校验所需权限。
- [ ] 测试群 `testChatId` 只用于 DEMO，不接收正式事故。
- [ ] P1 创建一个测试事故群。
- [ ] 负责人和备份负责人实际入群。
- [ ] 卡片在飞书客户端正常渲染，负责人实际收到 `@`。
- [ ] 点击“认领并处理”后状态为 `ACKED`。
- [ ] 点击“更新为处理中”后状态为 `PROCESSING`。
- [ ] 点击“标记恢复”后状态为 `RECOVERED`。
- [ ] 恢复卡片发送到同一事故群。
- [ ] 恢复后不再收到未处理提醒。
- [ ] 断网、超时和上游拒绝对应状态符合规格。

真实飞书验收完成后记录群名、`chat_id`、消息 ID 和回调事件 ID；不得记录凭证。

## 5. 生产 MySQL 迁移

执行前必须单独确认：

- [ ] 已备份目标库。
- [ ] 已只读确认 `app_config` 和 `notification_delivery` 当前结构。
- [ ] 已确认没有同名 `alert_event`、`alert_incident`。
- [ ] 已确认 `006_incident_alerts.sql` 只会新增表、列和索引。
- [ ] 已确认目标连接为生产库而不是本地或测试库。
- [ ] 执行后核对两个新表、四个新列和全部唯一索引。
- [ ] 用只读查询验证旧通知记录仍可读取。

禁止：

- 应用启动时自动执行迁移。
- 清空数据库或重放种子数据。
- 把测试 AppID、测试群或 fixture 数据写入生产。

4. 生产迁移经人工授权并核对完成。
