# CStore T06/T07 实施计划

使用 superpowers:executing-plans 顺序执行，先Java后Vue。用户提供的截图分析作为本轮协议依据，未声称已读取原截图或登录SWQA。真实Base URL/鉴权/映射/测试文件仍缺，本轮不以本地夹具代替真实接入验收。

架构：Spring Boot RestClient 对接 POST `/cstore/api/v3/downloadUrl`（appId字符串、fileKeys数组）与 POST `/cstore/api/v2/file/meta`（appId数值、fileKeys最多10）。v3仅发送isTmp/isInternal/isCustomStorage=false，不自行推断有效期；v2 fsize按已显式确认B单位处理。Vue复用现有表格与详情。

业务接口：POST `/api/v1/files/metadata` 请求 `{runId,fileKeys}`，POST `/api/v1/files/access-url` 请求 `{runId,fileKey,purpose}`。前端只给业务运行/文件标识，Java读取可信快照核对App/文件/REAL数据来源；MOCK预测不影响REAL文件身份，FAKE数据拒绝真实访问。配置映射区分v3字符串和v2数值AppID，fileKey需显式EXACT或逐项映射，绝不剥离URL域名推断。

业务响应统一包含runId/appId/业务fileKey、dataSource(CSTORE/CSTORE_TEST)、queriedAt；元信息每条包含fileSizeBytes精确字符串或null、contentType、status和脱敏errorCode；访问返回url与expiresAt=null（上游当前协议未提供响应有效期）。Cache-Control:no-store；客户端fetch也no-store。URL仅当前详情内存，关闭/切文件/请求失败清除；不进入DB、快照、localStorage/sessionStorage或日志。

限流：单实例全局共享滑动1秒20个上游HTTP请求（可配置1～100）、同时在途2个（可配置1～5）；无界队列/重试均不引入，容量不足429。metadata上限50文件，按10分批；单文件失败不置0、不阻断其他文件。多实例上线前需共享出口限额，本轮不引入Redis。

配置从进程环境读取：Base URL、鉴权Header名/值或明确无需鉴权、App映射JSON、B单位确认、LIVE/TEST模式、QPS/并发。缺失返回明确未配置错误。凭证与映射值不打印；不记录上游错误体或签名URL。
