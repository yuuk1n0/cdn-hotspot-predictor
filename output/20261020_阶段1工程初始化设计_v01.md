# 阶段 1 工程初始化设计

## 1. 目标

只建立三个可独立启动的最小工程，并验证 Vue 3、Spring Boot + MySQL、FastAPI 的基础连通性。不实现 CSV 导入、预测任务、榜单或其他业务功能。

## 2. 材料核对结论

- 考核题最终要求覆盖动态预测与滚动回测、Top50 看板、压缩效果、CStore、飞书通知和 Agent。
- 当前分阶段方案与最小化设计的职责边界一致：CSV 上传与质量检查归 Python；业务任务归 Java；Vue 分别调用两个服务；预测 Mock 只存在于 Python 内部。
- V1 将 CSV 导入闭环列为第一步，当前指令则明确阶段 1 只能初始化工程。阶段 1 以当前指令为准，不创建导入接口。
- `10066.csv` 与 `10350.csv` 均为 GB18030 编码，字段名称不一致，且文件标识同时存在完整 URL 与相对路径。
- `10066.csv` 有 1,048,575 条数据，覆盖 2026-01-01 至 2026-04-16，每日 124 至 13,038 条，不符合“每日 Top100”描述。文件数据行数恰好等于 Excel 最大行数减一，且最后一天仅 124 条，因此存在被 Excel 截断的风险；这是基于文件特征的推断，后续需向数据提供方确认。
- `10350.csv` 有 4,478 条数据，覆盖 2026-01-05 至 2026-10-13，共 248 个有数据日期、34 个缺失日期；862 条流量使用科学计数法，但可解析为整数。
- 两份数据均未发现重复的 `(日期, AppID, 文件标识)` 组合。

## 3. 最小架构

```text
Vue 3 :5173
  ├── /api/health      -> Vite 代理 -> Spring Boot /api/v1/health :8080
  └── /data-api/health -> Vite 代理 -> FastAPI /api/v1/health :8000

Spring Boot :8080
  └── MySQL SELECT 1 -> MySQL :3306
```

三个应用均提供最小启动入口。Vue 页面只展示连接状态，属于工程验证能力，不属于业务功能。

## 5. 技术选择

- 前端：Vue 3 + Vite，使用 JavaScript，避免阶段 1 引入路由、状态库和 UI 组件库。
- Java：JDK 21、Spring Boot 3.3.5、Spring Web、JDBC、MySQL Connector/J。
- Python：Conda 环境 `cdn-predictor`、Python 3.11、FastAPI、Uvicorn。
- 数据库：MySQL 8；本机优先使用已安装的 MySQL，`compose.yaml` 作为具备 Docker 环境时的可选启动方式。
- 跨域：Java 和 Python 仅允许配置的前端开发地址，默认 `http://localhost:5173`。

## 6. 健康检查行为

- FastAPI 健康检查成功返回服务名和 `UP`。
- Java 健康检查成功时返回服务名、应用状态和数据库状态；MySQL 不可用时返回 HTTP 503 和 `DOWN`，应用进程仍可启动。
- Vue 并行请求两个健康检查，通过页面明确展示连接成功或失败，不伪造在线状态。

## 7. 当前阻塞与边界

- 当前 WSL 未启用 Docker，因此不能用 Compose 作为本机验证前提。
- 本机已安装 `mysqld` 和 MySQL 客户端，可用于阶段 1 数据库连通验证；若系统服务无权启动，将如实记录该环境阻塞。
- 阶段 1 不读取 CSV、不建业务表、不实现 Mock 预测。
