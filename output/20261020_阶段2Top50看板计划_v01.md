# 阶段 2 Top50 数据看板实施计划

> **执行方式：** 当前会话内联执行。遵循测试先行；未经用户确认不提交 Git。

**目标：** 用少量 MySQL Fake 数据完成 Top50 看板真实查询、组合筛选、状态反馈和分页闭环。

**架构：** Vue 通过现有 `/api` Vite 代理访问 Spring Boot；Spring Boot 使用 Spring JDBC 查询 MySQL。FastAPI 不参与本阶段。

**技术栈：** Vue 3、Vite、Node 内置测试；Java 21、Spring Boot 3.3.5、Spring JDBC；MySQL 8。

## 全局约束

- 不新增前端运行时依赖，不引入 ORM、缓存、消息队列或其他基础设施。
- Fake 预测结果必须在 API 和页面中明确标识。
- 所有筛选条件必须进入后端 SQL 查询，前端不做业务数据本地筛选。
- 不实现详情、压缩操作、CStore、Python 预测、收益、通知或 Agent。
- 保留用户已有 `datasets/` 与 `materials/` 状态，不提交 Git。
