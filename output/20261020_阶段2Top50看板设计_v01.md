# 阶段 2 Top50 数据看板设计

## 1. 目标与边界

本阶段只实现 `MySQL Fake 数据 -> Spring Boot 查询 API -> Vue3 看板筛选与展示`。查询链路真实，预测结果为明确标识的演示数据。不调用 FastAPI，不实现预测任务、详情、压缩操作、CStore、收益、通知或 Agent。

## 2. 最小方案

- MySQL 新增单表 `top50_prediction`，只保存看板所需字段；`schema.sql` 与 `data.sql` 可重复初始化。
- Spring Boot 使用现有 Spring JDBC，按 `Controller -> Service -> Repository` 三层实现，不增加 ORM、缓存或额外基础设施。
- 提供 `GET /api/v1/top50` 与 `GET /api/v1/top50/options` 两个只读接口。
- Vue 保持单页应用，不引入路由、状态库或表格组件库；使用原生表单、表格和分页按钮。

## 3. 数据契约

查询参数：`startDate`、`endDate`、`appId`、`granularity`、`modelVersion`、`compressionStatus`、`page`、`pageSize`。日期使用 `YYYY-MM-DD`；粒度为 `DAILY/WEEKLY`；分页从 1 开始且每页最多 50 条。

列表字段：`predictionDate`、`appId`、`granularity`、`rank`、`fileKey`、`fileType`、`fileSizeBytes`、`predictedBytes`、`score`、`reason`、`recentActualBytes`、`compressionStatus`、`modelVersion`。字节数通过 JSON 字符串传输，避免 JavaScript 整数精度问题。

响应固定包含 `dataSource: "FAKE"` 和演示数据说明，避免将样例预测结果伪装为真实算法产物。

## 4. 数据与筛选

Fake 数据覆盖两个 App ID、多个预测日期、日/周粒度、三个模型版本、四类文件和三种压缩状态。所有筛选条件进入后端 SQL `WHERE` 条件；前端不在本地筛选业务数据。

候选项按预测日期倒序，再按 App、粒度、模型和全局排名排序。相同预测组合内，排名与预测流量保持基本一致。

## 5. 页面设计

页面定位为 CDN 运营控制台：深海蓝、信号青与告警橙组成高密度数据界面；等宽字体用于排名、字节数和模型版本。顶部明确显示“演示数据”，中部为完整筛选区，下方为横向可滚动表格。

页面具备加载、失败、空数据和分页状态。详情、压缩等未开放功能不提供可点击入口。

## 6. 验证

- 后端单元测试验证参数和分页契约。
- 前端单元测试验证查询串、字节格式和失败响应。
- 启动本地 MySQL、Spring Boot、Vue 后，通过真实 HTTP 组合筛选核对返回数量与数据库查询结果。
- FastAPI 不参与本阶段链路。
