# 第⑤步 Java 获取结果与 Top50 快照实施计划

目标：只修改 backend，复用第三步持久任务、HTTP客户端和轮询机制。Python与前端现有未提交改动保持原样。不安装依赖、不提交/推送。

## 最小设计

- 从 Python `GET /api/v1/predictions/{runId}/items?page=1&pageSize=50` 获取已发布候选第一页。按V1设计不额外读取全部候选，不解析CSV或重算预测。
- 严格校验运行关联、来源、窗口、分页、总数、唯一身份、全局名次、流量与排序；错误不修补。保留原始标识和十进制流量字符串，BigDecimal只求Top50窗口累计合计，不再乘7。
- 新增独立 `prediction_run` 表保存JSON快照、taskId与来源，runId主键、taskId唯一；不写入 `top50_prediction`，不修改历史003迁移或种子。
- 保持 prediction_task 表结构不变；任务查询通过关联成功快照提供业务runId和predictionSource。
- 发布事务锁定任务，检查状态和原截止时间，写入完整快照并更新SUCCEEDED；失败回滚，原快照不可覆盖。数据库/网络暂时错误保持可重试任务，重启继续读取原Python任务及runId。
- 新增Java `GET /api/v1/predictions/{runId}`，只查询本地已成功发布快照，不依赖Python在线。未知属性保持null；热点占比不可计算。
- 新增迁移004仅编写，实际MySQL执行必须另获批准；H2测试fixture仅用于隔离测试库。
